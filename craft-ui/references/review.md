# 仕上げのチェック

変更した画面ごとに、すべての質問に「はい」と答えられるまで直す。

## 構造
- [ ] 画面の focal point は 1 つで、最大の文字サイズ・最も強い色を使っているのはそれだけか
- [ ] 機能の region（ヘッダー、ナビ、一覧、各パネル、LP の各セクション）は、面の色か境界線で区切られているか
- [ ] region の中の item は、箱ではなく罫線と余白で区切られているか
- [ ] 影は、画面に重なるものにだけ付いているか

## 値（audit.py で確認）
- [ ] 文字サイズ・太さ・角丸・余白がスケールの中にあるか（audit.py の ERROR が 0）
- [ ] 数字に `num`（等幅数字）が付いているか。数字の列は右寄せか

## 色
- [ ] ブランド色の塗りは、主操作と進捗の現在地だけか
- [ ] 今いる場所は **location**、押し込まれた切替は **toggle** で示されているか
- [ ] 状態・分類の色は、意味ごとに一貫しているか（同じ意味に同じ色、違う意味に違う色）
- [ ] 色だけで意味を伝えている所はないか（文字かアイコンでも示す）
- [ ] 新しく色を足した場合、palette.py の検査かそれと同等の計算で 4.5:1 以上を確認したか

## 状態と文言
- [ ] データを表示する画面に、空・読み込み中・エラー・権限なし・保存中の 5 状態があるか
- [ ] 長い名前・長い数字・0 件・1000 件で崩れないか
- [ ] ボタンの文言は結果を表す動詞か。エラーは直し方まで書いてあるか

## 操作
- [ ] キーボードだけで、すべての操作ができるか。フォーカスが見えるか
- [ ] ダイアログを開くとフォーカスが中に移り、閉じると元に戻るか
- [ ] モバイルでは、タップ領域が 44px 以上、入力欄が 16px 以上か
- [ ] `prefers-reduced-motion` で動きが止まるか

## テンプレートっぽさの直し方
テンプレートのように見えるのは、特定の見た目の組み合わせが、中身と関係なく使われるとき。次の形になっていたら、右側に置き換える。

| こうなっていたら | こう置き換える |
|---|---|
| すべての塊が同じ白い箱（同じ角丸・同じ影） | region だけを面と境界線で区切り、item は罫線にする |
| 紫〜青のグラデーションのヒーロー、グラデーションの文字 | 地は無地。見出しは `foreground` の単色。色は主ボタンだけ |
| 同じ形のカードが 3 つ並ぶ特徴紹介 | 内容の重さに合わせた形（左右交互、表、1 つを大きく） |
| 01 / 02 / 03 の番号 | 順番がある内容にだけ番号を付ける。それ以外は見出しだけ |
| 絵文字をセクションの目印にする | アイコンか、何も付けない |
| 何でも中央揃え | 本文と見出しは左揃え。中央はヒーローの短い見出しなど一部だけ |
| 斜体・細長い書体・斜めの形を飾りに使う | ブランドの指定がなければ、正体の Noto Sans JP と直線・角丸 |
| 灰色の文字が薄すぎる | `muted-foreground` 以上の濃さ（すべて 4.5:1 以上） |
| 「次世代の」「〜を実現」などの言葉 | 対象・数字・結果を具体的に書く |
| 太字が多い | 太字は見出しと重要な数字だけ。ラベルとボタンは 500 |
